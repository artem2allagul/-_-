## 1. Цель работы

Изучение базовых концепций контроля версий, приобретение практических навыков установки и настройки Git, создания локальных и удалённых репозиториев, а также организации структуры для хранения последующих лабораторных работ по программированию.

## 2. Краткие теоретические сведения

**Git** — распределённая система контроля версий. Она позволяет фиксировать изменения в файлах (делать «снимки» проекта — коммиты), возвращаться к предыдущим версиям кода и безопасно вести разработку.

**Локальный репозиторий** — скрытая папка `.git` на компьютере, где хранится вся история изменений проекта.

**Удалённый репозиторий** — копия проекта, размещённая на сервере в сети (в данной работе — на GitHub). Служит для резервного копирования и демонстрации кода.

**Коммит (commit)** — сохранённое состояние проекта с уникальным идентификатором. Каждое сохранение сопровождается осмысленным описанием выполненной работы.

**Основные команды:**

| Команда | Назначение |
|---|---|
| `git --version` | проверка установки Git |
| `git config --global` | задание имени и email пользователя |
| `git init` | создание локального репозитория |
| `git status` | просмотр состояния репозитория |
| `git add` | добавление изменений в область подготовленных файлов (индекс) |
| `git commit -m "..."` | фиксация подготовленных изменений с описанием |
| `git remote add origin <url>` | привязка удалённого репозитория |
| `git branch -M main` | переименование текущей ветки в `main` |
| `git push -u origin main` | отправка коммитов на GitHub |

**Markdown** — облегчённый язык разметки, на котором в дальнейшем оформляются отчёты к лабораторным работам.

## 3. Задание

1. Установить Git и проверить корректность установки.
2. Настроить имя и адрес электронной почты пользователя.
3. Создать корневую папку `programming-labs`, инициализировать в ней репозиторий и создать каталог `lab_01` с рабочим файлом.
4. Выполнить первый коммит.
5. Создать общедоступный (Public) репозиторий на GitHub без README, `.gitignore` и лицензии.
6. Связать локальный репозиторий с GitHub и отправить код командой `git push`.
7. Оформить отчёт в формате Markdown.

## 4. Ход выполнения работы

### 4.1. Установка Git

Установочный файл Git скачан с официального сайта git-scm.com, установка выполнена с параметрами по умолчанию. Корректность установки проверена командой:

```bash
git --version
```

### 4.2. Глобальная настройка Git

Для привязки к коммитам заданы имя и адрес электронной почты пользователя (тот же email, что использован при регистрации аккаунта на GitHub):

```bash
git config --global user.name
git config --global user.email
```

### 4.3. Создание структуры локального репозитория

```bash
mkdir programming-labs
cd programming-labs
git init
mkdir lab_01
```

В папке `lab_01` создан рабочий файл `main.py`.

Структура проекта:

```text
programming-labs/
├── .git/
└── lab_01/
    └── main.py
```

### 4.4. Первый коммит

```bash
git status
git add .
git commit -m "Initial commit: create structure and lab_01"
```

Перед `git add .` команда `git status` показывает `lab_01/` как неотслеживаемую (Untracked). После `git add .` файлы подготовлены к сохранению, а `git commit` фиксирует их в истории.

### 4.5. Создание репозитория на GitHub

На сайте github.com выполнено: **+ → New repository**, затем заданы параметры:

| Параметр | Значение |
|---|---|
| Repository name | `programming-labs` |
| Видимость | **Public** |
| Add a README file | не выбрано |
| Add .gitignore | не выбрано |
| Choose a license | не выбрано |

Все галочки инициализации оставлены пустыми, так как локальный код уже существует. Репозиторий создан кнопкой **Create repository**.

### 4.6. Связывание с GitHub и отправка кода

Локальный репозиторий связан с созданным удалённым репозиторием `programming-labs`, ветка переименована в `main`, после чего код отправлен на GitHub:

```bash
git remote add origin <адрес репозитория на GitHub>
git branch -M main
git push -u origin main
```

При первом `git push` выполнена авторизация на GitHub через браузер.

## 5. Результат выполнения

До первого коммита команда `git status` показывает папку `lab_01/` как неотслеживаемую:

```text
On branch master

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        lab_01/

nothing added to commit but untracked files present (use "git add" to track)
```

После `git add .` и `git commit` создан первый коммит с сообщением «Initial commit: create structure and lab_01». После выполнения `git push -u origin main` структура папки с `lab_01` появилась в общедоступном репозитории `programming-labs` на GitHub.

## 6. Выводы

В ходе лабораторной работы изучены базовые понятия контроля версий: локальный и удалённый репозитории, коммит. Выполнены установка и глобальная настройка Git, создан локальный репозиторий `programming-labs` со структурой каталогов для лабораторных работ и сделан первый коммит командами `git add` и `git commit`. На GitHub создан общедоступный репозиторий, который связан с локальным командой `git remote add origin`, а код отправлен командой `git push -u origin main`. Полученные навыки позволяют хранить все последующие лабораторные работы (`lab_02`, `lab_03` и т.д.) в одном репозитории и отправлять их на GitHub одной командой `git push`, а отчёты оформлять в формате Markdown.
